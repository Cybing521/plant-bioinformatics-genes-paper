## Manuscript wording (must stay in sync)

The manuscript's Data Availability section states three things: the processed tables and
the code are public; fine-tuned checkpoints are **not** deposited and third-party weights
are fetched rather than re-hosted; and the deposited code has **not** been verified
end-to-end against the runs that produced the reported numbers, so the deposited result
tables are the authoritative record.

This wording was **revised on 2026-10-02**. The earlier claim in this file — "fine-tuned
checkpoints are reproduced by retraining, not deposited" without the verification caveat —
overstated the reproducibility of the deposited code and no longer matches the manuscript.
Do not restore it.

## Figure regeneration

```bash
cd code/figures_src
MPLCONFIGDIR=/tmp/mplcache FIG_OUT=<输出目录> python3 -c \
  "import plot_figures as P; [f() for f in (P.plot_fig1,P.plot_fig2,P.plot_fig3,P.plot_fig4,P.plot_figs1,P.plot_figs2)]"
```

Paths are overridable via `FIG_REPO_ROOT` / `FIG_TABLES` / `FIG_OUT`. The script reads only
`results/` and writes only to `FIG_OUT`. The two style helpers it imports
(`style/house_flowchart.py`, `style/publication_style.py`) are vendored in this repository,
so no external directory has to be configured.

## Figure reproducibility check

**Re-running the figure script reproduces the deposited figures exactly.** Verified
2026-10-10 against `figures/`: all six PDFs regenerate byte-identical once the PDF
`CreationDate`, `ModDate` and `/ID` fields are normalised, and every file matches in byte
length.

matplotlib stamps a creation timestamp into the PDF header, so a raw `md5` comparison will
always differ. Do not treat an `md5` mismatch between a regenerated figure and `figures/` as
a defect; compare rendered content, or normalise the date fields first.

**This result is narrower than full reproducibility.** It says the deposited figures can be
rebuilt from the deposited tables and script. It says nothing about retraining the models,
which remains unverified (see the caveat above).

## Result table conversions

`results/excel/` is generated from `results/` and is never edited by hand:

```bash
python3 tools/make_excel_results.py     # tables -> .xlsx
python3 tools/make_results_readme.py    # table descriptions -> results/README.md
```

Both are derived artefacts. If a table in `results/` changes, regenerate both; the
descriptions live in `tools/make_excel_results.py` (`META`) and must be updated with it.
